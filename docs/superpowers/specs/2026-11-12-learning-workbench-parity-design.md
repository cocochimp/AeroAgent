# 学员工作台功能恢复与指标可观测设计

## 目标

将当前 React 规则演示升级为机票退改签辅导项目的完整学习工作台。学员在同一界面完成业务交互，并能观察 Agent 每一步的执行、检索、记忆、评测和安全校验。旧版已有功能必须逐项保留；这次是界面和体验升级，不删除旧业务链路。

## 现状依据

- 旧版 `web/` 提供对话、评测、规则、数据和配置五个页面；对话页执行面板有流程、检索、记忆和校验四个面板。
- `air_agent/` 已有规则模式图编排、工具调用、检索漏斗、记忆拼接、费用计算、结果校验和评测逻辑。
- 当前 React 版只覆盖简化对话与评测编辑；界面内置的 65/65 结果只校验意图识别，不等同于旧版的完整业务评测。
- 参考截图中的检索指标包括向量召回、BM25、RRF、硬过滤、精排、MMR 和上下文注入；示例数量与分数是一次运行结果，不应作为固定指标写进主链路。
- 旧版 `127.0.0.1:8770/#/rules` 在本次盘点中触发页面加载错误。规则库与检索调试器仍以旧版源代码能力为对照，重构后需通过可运行验收。

## 方法选择

1. **纯前端演示引擎**：依赖最少，但会复制 Python 业务逻辑，难以提供可信的 trace、检索指标和完整评测；不采用。
2. **React 工作台复用现有 Python 规则链路**：继续使用 `air_agent/` 的规划、工具、检索、记忆、费用、校验与评测；React 负责教学呈现，固定种子数据外置。该方案复用已有逻辑，指标可以从本次真实执行结果计算，采用此方案。
3. **另建平行演示服务**：与原链路隔离，但新增一套规则、评测和追踪实现，容易产生两套结果；不采用。

## 页面与功能范围

### 全局工作台

- 左侧导航：对话、评测、规则、数据、配置。
- 顶栏保留规则模式/DeepSeek 切换、用户及会员等级、检索后端状态、深浅色主题。
- 保留乘客视角/管理员视角切换；乘客视角只办理业务，管理员视角进入评测、规则、数据和配置管理。
- 页面面向学员而非终端消费者：业务结果和技术解释同时可见；不把关键运行状态藏在开发者控制台。
- 页面需适配宽屏和窄屏；窄屏时执行面板可折叠或改为抽屉，不隐藏其功能。

### 对话与业务办理

- 显示当前用户的演示客票、航班状态、票种和已办理状态；允许选择订单和切换用户。
- 保留自由输入及旧版快捷场景：改签差价、改签加退票、航班取消、指代追问、模糊日期、转人工。
- 展示意图/子诉求、追问、拒绝或转人工、适用规则、费用明细、确认提示和办理结果。
- 退改等高风险动作必须通过独立确认后才提交；不确认或取消时订单状态保持不变；重复确认不得重复办理。
- 规则模式离线可演示；DeepSeek 模式与配置、连接测试、失败降级行为继续保留。

### 运行解释面板

- **流程**：按事件顺序展示节点名称、结果状态、耗时和说明；展开后显示该节点输入与输出。支持追问、工具 Schema 校验、必经节点门禁、Step-back、自我修正、人工转接、确认和办理等实际出现的节点。
- **检索**：按本次运行数据呈现向量召回、BM25 召回、RRF 融合、硬过滤、精排、MMR、上下文注入的候选数、配置上限、阶段结果、候选规则和分数。显示当前 hybrid/fallback 状态、降级原因、查询改写及用户画像加权；点选规则可联动原文。
- **记忆**：呈现订单栈、滑动窗口轮数、摘要、用户画像、各上下文区块 Token 使用量/预算/截断状态、总预算和相对全量上下文节省比例。
- **校验**：呈现置信度和阈值、规则依据率、费用引擎与方案金额对比、无效规则引用、无依据断言、校验错误、修正次数与最终放行/拦截结果。
- 所有节点耗时、候选数、分数、Token 与校验状态来自真实运行对象。前端只格式化并可视化，不预置截图中的 `52/60`、`31/60` 等演示数值。

### 评测中心

- 恢复评测集搜索、按标签/航司/结局筛选、全选/单选、编辑、新建、复制、删除、导入、导出。
- 支持全量、筛选结果、已勾选范围；支持规则模式和 DeepSeek 模式；运行时显示进度和失败项。
- 指标恢复：方案正确率、工具调用准确率、政策命中率、转人工率、平均延迟、P95 延迟、平均 Token、用例数量；恢复航司×票种正确率热图、失败原因分布和失败用例下钻。
- 单例评测对比期望与实际的意图、工具序列、金额、规则 ID、结局、Schema 错误及禁止行为，并可查看该用例的完整 trace。
- 保存评测历史，支持查看历史运行和选取两次运行做指标差异及逐例结果翻转对比。
- 评测继续使用旧版 `eval/gold_cases.json` 数据结构和完整评测逻辑。禁止将仅意图匹配的 65/65 作为方案正确率或完整评测通过率。

### 规则库

- 恢复按 ID、标题、内容及航司、舱位、票种、场景筛选规则；支持新增、编辑和删除。
- 恢复检索调试器，可输入问题、选择检索过滤和画像用户，查看完整漏斗；可从候选规则联动定位原规则。
- 规则变更后按现有机制更新搜索索引，规则原文仍是回答政策依据，费用仍由运价引擎计算。

### 数据管理

- 恢复用户画像浏览、订单表、航班正常/延误/取消状态修改、延误分钟输入、长期画像清理及演示数据重置。
- 仅处理虚构演示数据；状态变化应通过既有业务计算反映到后续会话和费用，不只更新页面标签。

### 配置中心

- 恢复决策模式与 DeepSeek 连接配置和测试、Query 追问阈值及 Step-back 触发、检索后端与各阶段 k/阈值/RRF/MMR/画像权重、记忆 Token 预算/窗口/订单栈/区块份额、质量阈值/最大修正次数、ReAct 最大轮数/工具参数重试。
- 保留字段范围校验、内存份额合计提示、未保存状态、保存生效、恢复默认和 Secret 不回显。
- 检索面板显示的配置上限必须读取当前配置；更改后下一次运行应反映新设置。

## 数据与运行边界

- 新建 `demo_data/` 保存可编辑的演示种子数据，例如 `users.json`、`orders.json`、`profiles.json`、`rules.json` 和 `scenarios/`。页面和业务代码不得散落重复的虚构订单/规则常量。
- `eval/gold_cases.json` 继续作为评测集的单一仓库副本，不复制到演示订单文件中。
- **DDD FastAPI 是 React 工作台唯一 API 入口，PostgreSQL 是工作台业务权威库**：用户/画像、航班/订单、费用规则/政策规则、案件、报价、交易操作、账务记录、评测集/评测运行、审计事件与案件 trace 均以 PostgreSQL 为准。
- `air_agent/` 继续承载现有 Agent 编排、检索、记忆拼接和校验实现；由 `backend/app` 的应用服务与适配器调用。把其直接访问 `air_agent.data` 的业务读取/写入收敛到存储边界，工作台执行不得以 SQLite 作为另一份业务事实源。需要持久化的会话记忆和 trace 由 PostgreSQL/案件事件存储承接；检索索引可由 PostgreSQL 规则投影重建。
- 旧 `web/` + 根 `app.py` 仍保留为独立的旧版回退入口，可继续使用原 SQLite 数据库；它不是 React 工作台的数据写入口。两套入口使用同一份 `demo_data/` 和 `eval/gold_cases.json` 种子定义，但运行期数据库彼此隔离，避免无主双写。
- 版本化业务 API 总数保持不超过 15：优先扩展现有资源接口；订单查询支持管理员工作区数据，订单命令接口用动作类型承接航班状态修改/画像清理/数据重置；评测列表接口支持按视图读取历史运行和单次运行详情。
- 运行期状态与静态种子文件分开；用户重置工作台演示数据时，从 `demo_data/` 初始化 PostgreSQL，并重建检索索引。
- 检索/流程/记忆/校验指标由复用链路的本次结果生成。场景文件仅定义输入与预期，不缓存截图式的指标值。
- 不要求真实航司、GDS 或支付连接；所有交易是清楚标注的 mock 操作。

## 保留与迁移约束

- React 是新工作台的默认入口；旧 `web/` + `app.py` 在逐项功能对照与验收前保留为可运行的参考/回退路径。
- 不删除或弱化 `air_agent/`、`eval/`、当前 `backend/` 及其业务逻辑。`backend/app` 的 DDD API 与 PostgreSQL 是新工作台的接口/业务事实源；旧 Agent 算法通过适配器复用。
- 不在本期执行 `backend/` → 根目录 `app/` 的包迁移。该目录调整仍需项目方单独审核。
- 旧版页面和 API 如与新 DDD 服务重复，应通过明确适配边界复用；不以临时复制逻辑替代。

## 验收标准

1. 五个旧版导航页面和顶栏模式、用户、检索状态、主题操作在新工作台可用。
2. 六类快捷场景可演示；报价/校验/确认/完成节点与订单变更一致；取消确认不改变订单。
3. 一次规则模式退改请求可在右侧查看完整 trace、检索漏斗、上下文预算和校验详情；指标随输入、配置和数据变化。
4. 截图展示的检索阶段均可见，阶段数值来自真实检索结果，并可查看各阶段候选项。
5. 评测增删改、导入导出、过滤、范围运行、规则/DeepSeek 模式、完整评分、历史查看/对比及用例下钻均可用。
6. 规则编辑和检索调试、数据管理与重置、全部配置项可用且与后续运行生效联动。
7. 所有核心页面在规则模式、无 DeepSeek Key、仅本地演示环境下可以打开；相关运行错误不得静默吞掉。
8. 与旧版功能清单逐项核对；新 React 路径通过行为测试、完整评测集运行、前端构建和浏览器端宽/窄屏检查后，才可考虑旧 UI 退役。

## 已确认的设计基线与待实现选择

- 项目方已认可“React 工作台 + DDD API/PostgreSQL + 现有 `air_agent` 执行引擎”的方向；新 React 工作台默认走 DDD API，根 `app.py` 旧接口不作为新 UI 服务入口。
- 项目方已认可新增 `demo_data/` 存放静态种子和场景；业务变更、会话记忆、trace 和评测运行统一持久化到 DDD PostgreSQL。旧入口仍可使用自身 SQLite，但与新工作台隔离。
- 具体页面组件划分、API 适配位置和运行时事件 DTO 可在获批后由实施计划确定，但不得删减上述功能与指标。
