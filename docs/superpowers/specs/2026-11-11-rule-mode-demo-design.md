# 规则模式可演示闭环设计

## 目标

让学员无需 Docker、数据库或 DeepSeek，也能从乘客退改请求走到报价确认和模拟办理；管理员能编辑并运行项目现有格式的评测集。

## 设计

前端增加确定性规则模拟服务，提供固定演示订单、退改资格、费用计算、报价、确认办理和评测运行。界面数据存入 `localStorage`，切换角色和刷新页面后保留。模拟服务独立于 React 组件，后续可替换为 FastAPI 适配器。

乘客工作台列出本人客票，直接显示可退/不可退、可改/不可改、原因和适用规则；乘客可选择订单、输入退改诉求、查看明细、确认并完成模拟操作。管理员可查看、编辑、新增、删除、校验、保存评测集，并运行规则模式评测及查看结果。

评测沿用 `eval/gold_cases.json` 的 `id/question/expect` 结构。规则模式按意图和可办理性评估，不调用 DeepSeek。页面须清楚标示所有数据与办理均为虚构模拟结果。

## 范围与限制

- 本次不改变 Python `backend/` 目录结构，不迁移、不重命名、不改 imports。
- 本次不依赖 Docker、PostgreSQL、Redis、Qdrant 或外部 LLM。
- 规则模式本地运行结果不代表现有后端生产交易链路已接通。

## 验收

1. 新会话打开后可见演示订单及每张票的退改资格。
2. 改签、退票请求均能展示规则依据和费用明细；用户确认后显示成功办理或明确拒绝原因。
3. 刷新后订单、案件和模拟办理结果仍在；管理员评测集改动也保留。
4. 管理员可编辑/保存/运行评测集，查看通过数和失败用例。
5. 规则服务单元测试和生产构建通过。
